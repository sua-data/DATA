## 1. 오늘 한 작업
- 이메일 인증 기능에 필요한 email_verifications 테이블 구조를 정리했다.
- 인증번호, 인증 여부, 만료 여부, 시도 횟수, 만료 시간을 저장할 수 있도록 컬럼을 구성했다.
- 회원가입할 때 이메일 중복 확인 후 인증번호를 보내고, 사용자가 입력한 인증번호를 검증하는 흐름을 정리했다.
- 인증번호를 여러 번 요청했을 때 최신 인증번호를 기준으로 처리해야 한다는 점을 고려했다.
- 조회 성능을 위해 email, created_at 기준 인덱스도 같이 생각했다.

---

## 2. 어려웠던 점
- 처음에는 인증번호만 저장하면 될 줄 알았는데, 막상 생각해보니 이미 인증된 번호인지, 만료된 번호인지, 최신 번호인지 구분이 필요했다.
- 사용자가 인증번호를 여러 번 요청하면 이전 번호와 새 번호를 어떻게 처리해야 할지 헷갈렸다.
- 테이블을 만들고 나서 필요한 컬럼이 빠진 걸 발견해서 다시 삭제하고 만드는 과정도 있었다.
- 인증 테이블은 users 테이블과 연결되지만, 회원가입 전에도 이메일 인증이 필요해서 구조를 어떻게 잡을지 고민됐다.

---

## 3. 해결한 방법
- is_verified 컬럼으로 인증 완료 여부를 관리했다.
- expires_at과 is_expired로 인증번호 만료 여부를 관리했다.
- attempt_count로 인증번호 입력 시도 횟수를 저장할 수 있도록 했다.
- 최신 인증번호를 확인할 수 있도록 email과 created_at 기준 조회를 고려했다.
- 회원가입 전 단계에서 사용하는 테이블이므로 users와 너무 강하게 묶기보다는 이메일 기준으로 관리하는 방향으로 정리했다.
- 빠진 컬럼이 있으면 테이블을 다시 만들면서 구조를 맞췄다.

---

## 4. 느낀 점
- 이메일 인증은 단순한 숫자 비교가 아니라 상태 관리에 가까웠다.
- 처음부터 완벽한 테이블을 만들기는 어렵고, 실제 기능 흐름을 생각하면서 계속 다듬어야 했다.
- 테이블을 지웠다가 다시 만드는 과정이 귀찮긴 했지만, 그 과정에서 구조가 더 명확해졌다.
