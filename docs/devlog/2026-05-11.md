## 1. 오늘 한 작업
- 메인 페이지의 1위 키워드 영역에 필요한 데이터 구조를 정리했다.
- 전일 00:00부터 당일 00:00까지 수집된 기사 기준으로 키워드를 집계하는 흐름을 점검했다.
- 키워드별 기사 수를 기준으로 Top5 키워드를 뽑는 방식을 확인했다.
- 1위 키워드에 포함된 기사들을 기준으로 긍정/중립/부정 감성 비율을 계산하는 흐름을 정리했다.
- 백엔드에서 1위 키워드, 기사 수, 감성 비율, Top5 키워드를 API 응답으로 내려주는 구조를 검토했다.
- 기사 목록 API에서 최신 기사들이 정상적으로 내려오는지 확인했다.
- 기사 목록에서 특정 기사를 클릭했을 때 article_id를 기준으로 기사 상세 페이지로 이동하는 흐름을 점검했다.
- 마이페이지의 내가 본 뉴스 목록에서 기사를 클릭하면 해당 기사 상세 페이지로 이동하도록 연결했다.
- 기사 상세 화면에서 감성값이 positive, negative, neutral로 보이는 문제를 긍정, 부정, 중립으로 표시되도록 정리했다.

---

## 2. 어려웠던 점
- 1위 키워드는 단순히 키워드 하나만 뽑으면 되는 기능이 아니라, 집계 기준과 감성 비율 계산까지 같이 맞춰야 했다.
- 키워드를 단어 등장 횟수로 계산할지, 해당 키워드를 포함한 기사 수로 계산할지 기준을 명확히 해야 했다.
- 같은 기사 안에서 동일 키워드가 여러 번 등장할 수 있어서 단순 빈도 기준으로 하면 결과가 왜곡될 수 있었다.
- 기사 목록, 기사 상세, 마이페이지 조회 기록이 모두 article_id로 이어져야 해서 데이터 흐름이 끊기지 않도록 확인해야 했다.
- 기사 상세 페이지에서는 ES에서 가져오는 기사 데이터와 DB에 저장되는 조회 기록 데이터가 함께 맞물려야 했다.
- 감성값은 데이터에는 영어 라벨로 저장되어 있지만, 사용자 화면에서는 한글로 보여야 해서 표시값 변환이 필요했다.

---

## 3. 해결한 방법
- 키워드 집계는 단어 등장 횟수가 아니라 “해당 키워드를 포함한 기사 수” 기준으로 정리했다.
- 같은 기사 안에서 같은 키워드가 여러 번 등장해도 기사 수 기준으로는 1회만 집계하는 방향으로 잡았다.
- 1위 키워드 API는 top_keyword, article_count, sentiment_distribution, top5_keywords를 내려주는 구조로 정리했다.
- 기사 목록과 마이페이지에서 상세 페이지로 이동할 때 article_id를 전달하도록 흐름을 맞췄다.
- 기사 상세 페이지에서는 전달받은 article_id를 기준으로 ES의 기사 데이터를 조회하도록 정리했다.
- 조회 기록은 DB에 저장하되, 화면에 보여줄 기사 정보는 ES에서 가져오는 구조로 이해하고 연결했다.
- 감성값은 화면 출력 전에 positive, negative, neutral을 각각 긍정, 부정, 중립으로 변환하도록 했다.

---

## 4. 느낀 점
- 메인 페이지의 작은 1위 키워드 영역도 실제로는 배치 집계, ES 데이터, API 응답, 프론트 표시가 모두 연결된 기능이었다.
- 집계 기준을 명확히 정하지 않으면 같은 데이터라도 결과가 다르게 나올 수 있다는 점을 느꼈다.
- article_id를 공통 기준으로 잡아둔 덕분에 기사 목록, 상세 페이지, 마이페이지 조회 기록을 연결할 수 있었다.
- 백엔드 데이터 구조와 프론트 표시 방식은 다를 수 있어서 사용자에게 보여줄 값은 따로 변환해야 했다.
- 기능 하나를 연결할 때도 DB, ES, API, 화면 흐름을 같이 봐야 한다는 점을 다시 확인했다.
