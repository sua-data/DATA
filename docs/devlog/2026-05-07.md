## 1. 오늘 한 작업
- 여러 페이지에 공통 header와 footer를 적용하는 작업을 진행했다.
- main.html 기준의 상단바 디자인을 article_list, scope_detail, viewpoint_detail, mypage_home 등에 맞춰 적용했다.
- header.html과 footer.html을 fetch로 불러오는 구조를 정리했다.
- Figma에서 잡힌 전체 화면 분위기와 실제 HTML/CSS 화면이 어긋나는 부분을 확인하며 여백, 정렬, 색상, 폰트 크기를 조정했다.
- 라이트모드/다크모드가 페이지마다 따로 동작하지 않고 전체 페이지에서 동일하게 적용되도록 localStorage 기반으로 정리했다.
- 검색 자동완성 UI와 기능이 여러 페이지에서 동일하게 보이도록 CSS와 JS 구조를 맞추었다.
- footer 위치, 너비, 약관 모달 위치 문제를 점검했다.

---

## 2. 어려웠던 점
- Figma 화면을 실제 코드로 옮기는 과정이 익숙하지 않아 여백, 정렬, 색상, 폰트 크기를 맞추는 데 시간이 걸렸다.
- 처음에는 Figma를 보고 그대로 만들면 될 것 같았는데, 막상 HTML/CSS로 옮기면 화면 비율이나 간격이 다르게 보였다.
- 각 페이지마다 기존 CSS 구조가 달라 같은 header/footer를 넣어도 화면이 동일하게 보이지 않았다.
- 상단바를 고정하면 일부 페이지에서 레이아웃이 밀리거나 깨지는 문제가 있었다.
- footer를 화면 아래에 붙이거나 header처럼 양옆으로 꽉 차게 만드는 과정에서 페이지 전체 레이아웃이 밀리는 문제가 있었다.
- footer 안에 약관 모달을 넣었더니 모달이 화면 중앙이 아니라 아래쪽에 뜨는 문제가 있었다.
- 검색 자동완성 박스도 페이지마다 위치와 크기가 다르게 보여 공통화가 필요했다.
- 라이트모드/다크모드가 페이지마다 따로 적용되는 느낌이 있어 전체 페이지 공통 상태로 관리할 필요가 있었다.

---

## 3. 해결한 방법
- main.html을 기준 화면으로 정하고, 다른 페이지의 header/footer와 검색창 스타일을 해당 기준에 맞췄다.
- Figma 화면을 무조건 그대로 따라 하기보다 공통 여백, 색상, 폰트 크기, 컴포넌트 위치를 기준화해서 적용했다.
- header.html과 footer.html을 공통 파일로 분리하고 각 페이지에서 fetch로 불러오도록 구성했다.
- 라이트모드/다크모드는 localStorage에 저장된 값을 기준으로 모든 페이지에서 동일하게 적용되도록 했다.
- 약관 모달은 footer 위치의 영향을 받지 않도록 fixed 기반 구조로 수정했다.
- 각 페이지에 남아 있던 하드코딩된 header/footer 코드를 제거하고 공통 UI 기준으로 맞췄다.
- 검색 자동완성 CSS도 공통 스타일 기준으로 정리했다.

---

## 4. 느낀 점
- 프론트 작업은 단순히 화면을 만드는 것이 아니라 디자인 기준을 코드로 일관되게 옮기는 작업이었다.
- Figma를 잘 다루는 것보다 중요한 것은 디자인 요소를 구조화해서 HTML/CSS로 재현하는 능력이라는 걸 느꼈다.
- 공통 UI는 HTML만 분리한다고 끝나는 게 아니라 CSS와 JS 동작까지 함께 맞춰야 했다.
- 라이트모드/다크모드는 페이지별 기능이 아니라 사이트 전체 상태로 관리해야 했다.
- 모달은 부모 요소의 위치 영향을 받지 않도록 구조를 잡는 것이 중요했다.
