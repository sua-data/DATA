## 1. 오늘 한 작업
- 일별 키워드 집계 구조를 정리했다.
- daily_keyword_metrics 인덱스를 기준으로 날짜별 키워드 기사 수를 저장하는 방식을 검토했다.
- 메인 페이지의 1위 키워드 영역 요구사항을 정리했다.
- 전일 00:00부터 당일 00:00까지의 기사 데이터를 기준으로 키워드를 집계하는 구조를 잡았다.
- 1위 키워드에 포함된 기사들의 긍정/중립/부정 비율을 보여주는 흐름을 정리했다.
- Top5 키워드와 키워드 상세 페이지 이동 흐름을 정리했다.
- 비로그인/로그인 상태에 따라 페이지 이동이 달라지는 부분을 정리했다.

---

## 2. 어려웠던 점
- 키워드를 단순 등장 횟수로 계산하면 한 기사에서 반복된 단어 때문에 순위가 왜곡될 수 있었다.
- 같은 키워드라도 기사 수 기준으로 볼지, 단어 등장 횟수 기준으로 볼지 정해야 했다.
- 메인 페이지에서는 간단히 보여줘야 하지만, 상세 페이지에서는 더 많은 분석 데이터를 보여줘야 해서 데이터 흐름을 나눠야 했다.
- 비로그인 사용자가 키워드를 클릭했을 때 바로 상세 페이지로 보내면 안 돼서 로그인 여부 처리를 같이 생각해야 했다.

---

## 3. 해결한 방법
- 키워드는 등장 횟수가 아니라 “해당 키워드를 포함한 기사 수” 기준으로 집계하기로 했다.
- 같은 기사 안에서 같은 키워드가 여러 번 등장해도 1회만 카운트하는 기준을 잡았다.
- 로그인 여부를 확인해 비로그인 사용자는 로그인 페이지로 이동시키고, 로그인 사용자는 키워드 상세 분석 페이지로 이동하도록 정리했다.
- 1위 키워드와 Top5 키워드는 메인에서 빠르게 탐색할 수 있는入口 역할로 설계했다.
- 일별 집계 결과는 daily_keyword_metrics와 daily_top_issue_report 구조로 나누어 관리하는 방향을 잡았다.

---

## 4. 느낀 점
- 집계 기준을 명확히 정하지 않으면 같은 데이터라도 해석이 달라질 수 있었다.
- 메인 화면의 데이터는 단순 출력이 아니라 사용자가 다음 행동을 하도록 연결하는 역할을 해야 했다.
- 데이터 구조와 화면 흐름은 따로가 아니라 같이 정리해야 했다.
