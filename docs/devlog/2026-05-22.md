# 2026-05-22 Devlog

## 오늘 한 작업

- 프로젝트 발표 자료에 들어갈 기능 흐름을 정리했다.
- 수집, 분석, 저장, 조회까지 이어지는 전체 구조를 발표용으로 단순화했다.
- 데이터 파이프라인과 시스템 구조를 설명하는 방식을 검토했다.
- 시연에서 사용할 대표 키워드와 화면 흐름을 점검했다.

## 내가 맡은 작업

- DB와 Elasticsearch 구조 설명을 발표 자료에 넣을 수 있도록 정리했다.
- 프로젝트의 주요 기능과 데이터 흐름을 연결해서 설명하는 문장을 작성했다.
- 내가 담당한 저장 구조 설계 부분을 발표에서 어떻게 설명할지 정리했다.

## 문제점

- 실제 구현 구조가 복잡해서 발표 자료에 그대로 넣으면 이해하기 어려울 수 있었다.
- 비전공자나 평가자가 봐도 이해할 수 있게 핵심만 정리해야 했다.
- 시연 화면만 보여주면 내부 분석 과정이 잘 드러나지 않을 수 있었다.

## 해결 방법

- 전체 구조를 수집 → 분석 → 저장 → 조회 흐름으로 단순화했다.
- DB는 정형 데이터 저장, Elasticsearch는 검색 및 분석 결과 조회라는 역할로 설명하기로 했다.
- 화면의 각 결과가 어떤 분석 단계에서 생성된 것인지 연결해서 설명할 수 있도록 정리했다.

## 배운 점

- 발표 자료에서는 구현 세부사항보다 전체 흐름과 문제 해결 방식을 명확히 전달하는 것이 중요하다는 점을 배웠다.
