# 2026-05-14 Devlog

## 오늘 한 작업

- 뉴스 수집 이후 전처리, 키워드 추출, 감성 분석, 요약 처리의 전체 흐름을 정리했다.
- 배치 처리 과정에서 각 단계의 입력과 출력 데이터를 확인했다.
- 분석 결과가 DB와 Elasticsearch에 저장되는 흐름을 검토했다.

## 내가 맡은 작업

- 수집 데이터와 분석 데이터의 저장 시점을 정리했다.
- 배치 처리 결과가 어떤 테이블 또는 인덱스로 들어가야 하는지 흐름을 문서화했다.
- 프로젝트 설명 자료에 넣을 데이터 파이프라인 구조를 정리했다.

## 문제점

- 수집, 전처리, 분석, 저장 단계가 서로 연결되어 있어 한 단계가 실패하면 이후 단계에도 영향을 줄 수 있었다.
- 분석 결과가 여러 저장소에 나뉘어 저장되기 때문에 전체 흐름을 설명하기 어려웠다.

## 해결 방법

- 수집 → 전처리 → 키워드 분석 → 감성 분석 → 요약 → 저장 순서로 흐름을 정리했다.
- 각 단계별 산출물을 구분해서 문서화했다.
- DB와 ES에 저장되는 데이터를 목적별로 나누어 설명할 수 있도록 구조를 정리했다.

## 배운 점

- 데이터 파이프라인은 코드만 작성하는 것이 아니라 단계별 책임을 명확히 나누는 것이 중요하다는 점을 배웠다.
