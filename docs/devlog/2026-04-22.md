## 1. 오늘 한 작업
- users 테이블을 중심으로 회원 관련 DB 구조를 정리했다.
- 일반 사용자, 관리자, 최고관리자를 구분할 수 있도록 role 컬럼 구조를 잡았다.
- 약관 정보를 저장하는 terms_metadata 테이블과 사용자 약관 동의 이력을 저장하는 user_terms_agreements 테이블을 설계했다.
- 회원가입, 로그인, 비밀번호 변경, 회원탈퇴에서 필요한 데이터 흐름을 같이 확인했다.
- 실제 CREATE TABLE 문을 작성하면서 FK를 어떻게 걸어야 할지도 같이 고민했다.

---

## 2. 어려웠던 점
- 처음에는 users 테이블 하나만 제대로 만들면 회원 기능이 될 줄 알았는데, 약관 동의 이력까지 생각하니 테이블이 더 필요했다.
- 약관은 나중에 버전이 바뀔 수 있어서 그냥 users 테이블에 동의 여부만 넣으면 안 될 것 같았다.
- 사용자 삭제 시 관련 약관 동의 기록, 조회 기록, 반응 기록을 같이 지울지 말지 고민이 됐다.
- FK를 걸려고 하니 참조되는 테이블이 먼저 있어야 해서 테이블 생성 순서도 신경 써야 했다.

---

## 3. 해결한 방법
- users 테이블을 기준 테이블로 먼저 두고, 다른 사용자 관련 테이블들이 user_id를 참조하도록 정리했다.
- 약관 원본은 terms_metadata에 저장하고, 사용자가 어떤 약관에 동의했는지는 user_terms_agreements에 따로 저장하도록 나눴다.
- 사용자와 직접 연결되는 이력성 데이터는 user_id를 FK로 연결했다.
- 회원 탈퇴 시 같이 삭제되어도 되는 데이터는 ON DELETE CASCADE 적용을 검토했다.
- 테이블을 실제로 만들어보면서 빠진 컬럼이나 어색한 구조를 수정했다.

---

## 4. 느낀 점
- 회원 기능은 단순히 아이디와 비밀번호 저장으로 끝나는 게 아니었다.
- 약관, 권한, 인증, 탈퇴까지 생각하면 사용자 테이블 주변 구조가 꽤 중요했다.
- DB 설계는 머릿속으로만 하면 놓치는 게 많고, 실제로 CREATE TABLE을 해봐야 보이는 문제가 있었다.
