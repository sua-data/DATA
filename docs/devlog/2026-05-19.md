# 2026-05-19 Devlog

## 오늘 한 작업

- 뉴스 이슈를 묶는 scope 개념을 정리했다.
- 같은 키워드라도 날짜와 뉴스 묶음에 따라 다른 이슈로 해석될 수 있다는 점을 검토했다.
- scope 분석 결과를 버전으로 관리하는 구조를 확인했다.

## 내가 맡은 작업

- 이슈 분석 단위를 저장하기 위한 구조를 정리했다.
- scope 관련 인덱스와 refresh queue 구조를 검토했다.
- 분석 결과가 갱신될 때 기존 결과와 새 결과를 어떻게 구분할지 정리했다.

## 문제점

- 뉴스 분석 결과는 시간이 지나면서 바뀔 수 있기 때문에 단순히 덮어쓰기만 하면 이전 분석 상태를 추적하기 어려웠다.
- 같은 키워드라도 새로운 뉴스가 추가되면 이슈 요약과 감성 분포가 달라질 수 있었다.

## 해결 방법

- scope version 개념을 활용해 분석 결과의 버전을 구분하는 방향으로 정리했다.
- 갱신이 필요한 이슈는 queue 형태로 관리하는 방식을 검토했다.
- 분석 결과의 변경 가능성을 고려한 저장 구조를 정리했다.

## 배운 점

- 분석 서비스에서는 결과가 한 번 생성되고 끝나는 것이 아니라 갱신과 버전 관리까지 고려해야 한다는 점을 배웠다.
