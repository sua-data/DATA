# 2026-05-12 Devlog

## 오늘 한 작업

- 경제 뉴스 분석 서비스의 전체 구조를 다시 정리했다.
- 뉴스 수집 데이터와 분석 결과 데이터를 어떤 기준으로 분리해서 저장할지 검토했다.
- MariaDB와 Elasticsearch의 역할을 나누는 방향을 정리했다.
- 프로젝트 요구사항 중 데이터 저장과 조회에 필요한 항목을 확인했다.

## 내가 맡은 작업

- DB에 저장해야 하는 데이터 항목을 정리했다.
- 뉴스 원문, 키워드 분석 결과, 감성 분석 결과, 일별 이슈 데이터를 분리해서 관리하는 구조를 검토했다.
- 프로젝트 산출물에 들어갈 저장 구조 설명 방향을 정리했다.

## 문제점

- 뉴스 원문 데이터와 분석 결과 데이터를 하나의 테이블에 모두 넣으면 관리가 복잡해질 수 있었다.
- 검색용 데이터와 통계용 데이터를 같은 방식으로 저장하면 조회 목적이 불명확해질 수 있었다.

## 해결 방법

- MariaDB는 정형 데이터와 관리용 데이터를 저장하는 역할로 정리했다.
- Elasticsearch는 뉴스 검색, 키워드 조회, 이슈 분석 결과 조회에 활용하는 방향으로 정리했다.
- 원본 데이터와 분석 결과를 분리해서 저장하는 구조로 방향을 잡았다.

## 배운 점

- 데이터 분석 프로젝트에서도 모델 성능뿐 아니라 저장 구조 설계가 중요하다는 점을 배웠다.
- DB와 검색 엔진을 함께 사용할 때는 각각의 역할을 명확히 나누는 것이 필요하다는 점을 알게 되었다.
