## 문제점

- 최종 발표에서는 프로젝트 전체를 제한된 시간 안에 설명해야 했다.
- 수집, 전처리, 키워드 분석, 감성 분석, 요약, 검색, 화면 제공까지 흐름이 길어 핵심을 압축해서 전달할 필요가 있었다.
- 팀 프로젝트이기 때문에 팀 전체 결과와 개인 기여도를 구분해서 설명해야 했다.

## 해결 방법

- 발표에서는 수집 → 분석 → 저장 → 조회 흐름을 기준으로 설명했다.
- DB는 정형 데이터 저장, Elasticsearch는 검색 및 분석 결과 조회 역할로 나누어 설명했다.
- 개인 기여도는 요구사항 정의 참여, DB 테이블 작성, Elasticsearch 인덱스 설계, 산출물 문서화 중심으로 정리했다.
- 시연에서는 대표 키워드를 기준으로 사용자가 분석 결과를 확인하는 흐름을 보여주었다.

## 배운 점

- 최종 발표를 통해 단순히 기능을 구현하는 것뿐 아니라, 프로젝트의 목적과 데이터 흐름을 설명하는 능력이 중요하다는 점을 배웠다.
- 팀 프로젝트를 포트폴리오로 활용하려면 개인 역할과 기여도를 구체적으로 정리해야 한다는 점을 알게 되었다.
- 데이터 분석 서비스에서는 모델 적용뿐 아니라 저장 구조, 검색 구조, 화면 제공 흐름까지 함께 설계해야 완성도 있는 서비스가 된다는 점을 배웠다.
