# 2026-05-21 Devlog

## 오늘 한 작업

- 뉴스 검색 기능과 키워드 기반 조회 기능을 검토했다.
- Elasticsearch를 활용한 검색 구조를 다시 확인했다.
- 사용자가 특정 키워드를 검색했을 때 어떤 결과를 보여줄지 정리했다.

## 내가 맡은 작업

- 검색 결과에 포함되어야 할 데이터 항목을 정리했다.
- 뉴스 제목, 본문, 키워드, 날짜, 언론사, 감성 분석 결과 등의 활용 방식을 검토했다.
- 검색용 인덱스와 분석용 인덱스의 역할 차이를 문서화했다.

## 문제점

- 단순 검색 결과만 제공하면 프로젝트의 분석 서비스 성격이 약해질 수 있었다.
- 검색 결과와 분석 결과를 함께 보여줄 수 있는 구조가 필요했다.

## 해결 방법

- 뉴스 검색 결과와 함께 키워드, 감성, 요약 정보를 활용하는 방향으로 정리했다.
- Elasticsearch는 검색에 강점이 있으므로 뉴스 원문 검색과 키워드 기반 조회에 활용하는 구조로 정리했다.

## 배운 점

- 검색 기능은 단순히 데이터를 찾는 기능이 아니라 분석 결과와 연결될 때 서비스 가치가 커진다는 점을 배웠다.
