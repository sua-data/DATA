# 2026-05-18 Devlog

## 오늘 한 작업

- 사용자 화면에서 필요한 데이터가 무엇인지 기준으로 API 응답 구조를 검토했다.
- 일별 주요 이슈, 키워드, 관련 뉴스, 감성 분포를 화면에 보여주는 흐름을 정리했다.
- 프론트엔드에서 사용하기 쉬운 데이터 형태를 고민했다.

## 내가 맡은 작업

- 화면 기능 기준으로 필요한 데이터 항목을 정리했다.
- DB와 Elasticsearch에서 가져와야 하는 데이터를 구분했다.
- API 응답에 포함되어야 할 주요 필드를 정리했다.

## 문제점

- 백엔드와 프론트엔드가 필요한 데이터 형태를 다르게 이해할 경우 화면 구현이 어려워질 수 있었다.
- 분석 결과가 여러 저장소에 분산되어 있어 한 화면에 보여줄 데이터를 조합해야 했다.

## 해결 방법

- 화면 단위로 필요한 데이터를 먼저 정리한 뒤, 그에 맞춰 저장 구조와 조회 구조를 검토했다.
- 주요 이슈 카드, 키워드 목록, 감성 분포, 관련 뉴스 리스트를 기준으로 응답 데이터를 나누어 생각했다.

## 배운 점

- API 설계는 DB 구조만 보고 만드는 것이 아니라 실제 화면에서 어떻게 사용할지를 기준으로 설계해야 한다는 점을 배웠다.
