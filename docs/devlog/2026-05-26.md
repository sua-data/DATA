# 2026-05-26 Devlog

## 오늘 한 작업

- 최종 발표 전 발표 자료와 발표 순서를 점검했다.
- 프로젝트의 기획 배경, 주요 기능, 데이터 흐름, DB/Elasticsearch 구조를 설명하는 문장을 정리했다.
- 팀원별 발표 파트를 맞추고 전체 흐름이 자연스럽게 이어지는지 검토했다.
- 시연 과정에서 보여줄 화면 순서와 설명 포인트를 확인했다.

## 내가 맡은 작업

- 내가 담당한 DB 테이블 작성, Elasticsearch 인덱스 설계, 요구사항 정의 참여 내용을 발표 자료에 반영했다.
- 데이터 저장 구조와 검색 구조를 설명할 수 있도록 발표 문장을 정리했다.
- 프로젝트 전체 흐름에서 내가 기여한 부분을 포트폴리오용 문장으로 정리했다.

## 문제점

- 프로젝트 구조가 복잡해서 발표에서 모든 내용을 설명하면 핵심이 흐려질 수 있었다.
- DB와 Elasticsearch 구조를 기술적으로만 설명하면 평가자가 서비스 흐름을 이해하기 어려울 수 있었다.
- 팀 프로젝트이다 보니 개인 기여도와 팀 전체 작업을 구분해서 설명할 필요가 있었다.

## 해결 방법

- 발표에서는 수집 → 분석 → 저장 → 조회 흐름을 기준으로 설명하기로 했다.
- DB는 정형 데이터 저장, Elasticsearch는 검색 및 분석 결과 조회 역할로 나누어 설명했다.
- 개인 역할은 요구사항 정의 참여, DB 테이블 작성, Elasticsearch 인덱스 설계, 문서화 중심으로 정리했다.

## 배운 점

- 발표 자료는 구현 내용을 모두 나열하는 것보다 핵심 흐름과 역할을 명확히 보여주는 것이 중요하다는 점을 배웠다.
- 기술 설명은 사용자가 보는 기능과 연결해서 설명해야 설득력이 높아진다는 점을 알게 되었다.
