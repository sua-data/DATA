# 2026-05-13 Devlog

## 오늘 한 작업

- 경제 뉴스 데이터를 이슈 단위로 묶기 위한 기준을 검토했다.
- 키워드 기반 분석 결과를 일별로 저장하는 방식을 정리했다.
- 일별 주요 키워드와 관련 뉴스 목록을 연결하는 구조를 검토했다.
- 화면에서 사용자가 날짜별 주요 이슈를 확인하는 흐름을 정리했다.

## 내가 맡은 작업

- 일별 키워드 통계 저장 구조를 정리했다.
- 뉴스별 키워드와 일별 키워드 통계를 분리해서 관리하는 방식을 검토했다.
- 화면 조회에 필요한 데이터 항목을 기준으로 DB와 ES 구조를 점검했다.

## 문제점

- 뉴스마다 키워드를 저장하는 것과 하루 단위 키워드 통계를 저장하는 것은 목적이 달랐다.
- 같은 키워드라도 날짜별로 등장 빈도와 관련 이슈가 달라질 수 있기 때문에 단순 저장만으로는 부족했다.

## 해결 방법

- 뉴스 단위 분석 결과와 일별 집계 결과를 분리하는 방향으로 정리했다.
- 일별 키워드 통계는 별도 구조로 관리하고, 관련 뉴스와 연결할 수 있도록 정리했다.
- 사용자가 날짜별 주요 이슈를 확인할 수 있도록 데이터 흐름을 정리했다.

## 배운 점

- 분석 결과를 저장할 때는 “어떻게 만들었는가”보다 “어떻게 조회될 것인가”를 먼저 고려해야 한다는 점을 배웠다.
