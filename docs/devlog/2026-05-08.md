## 1. 오늘 한 작업
- 기사 상세 페이지에서 감성 정보와 관점 정보를 보여주는 구조를 정리했다.
- ES 또는 DB에 저장된 positive, negative, neutral 값을 화면에서는 긍정, 부정, 중립으로 표시하도록 수정했다.
- 기사 원문 아래에 해당 기사의 관점 정보를 보여주고, 동의해요/반대해요를 받을 수 있는 흐름을 검토했다.
- 마이페이지에서 내가 본 뉴스 목록을 클릭하면 해당 기사 상세 페이지로 이동하도록 연결했다.
- article_list.html에서 관리자 로그인 시 “관리자페이지”가 아니라 “마이페이지”로 보이는 문제를 점검했다.
- 페이지별 header 권한 분기 로직을 확인했다.
- 공통 header/footer가 적용된 페이지에서 화면 깨짐이나 권한 표시 차이가 없는지 확인했다.

---

## 2. 어려웠던 점
- 감성 분석 결과가 positive, negative, neutral처럼 영어로 출력되어 사용자 화면에 어색했다.
- 관점 동의/반대 기능을 만들려면 기사마다 어떤 관점인지 먼저 화면에 보여줘야 했다.
- 내가 본 뉴스 목록에서 기사 상세 페이지로 이동하려면 article_id를 기준으로 연결해야 했다.
- 다른 페이지에서는 관리자 계정일 때 “관리자페이지”가 잘 보이는데 article_list.html에서는 “마이페이지”로 표시되는 차이가 있었다.
- 같은 header를 쓰는 것처럼 보여도 페이지마다 JS 로직이 달라 권한 표시가 다르게 동작할 수 있었다.
- 기사 상세 페이지는 ES의 기사 정보와 DB의 사용자 활동 데이터가 함께 필요해서 데이터 흐름을 맞춰야 했다.

---

## 3. 해결한 방법
- 감성값을 화면 출력 전에 한글 표시값으로 변환했다.
  - positive → 긍정
  - negative → 부정
  - neutral → 중립
- 기사 상세 페이지에 감성 정보와 관점 정보를 함께 보여주는 방향으로 정리했다.
- 마이페이지의 본 뉴스 목록에서 article_id를 쿼리스트링으로 넘겨 상세 페이지로 이동하도록 흐름을 맞췄다.
- header에서 사용자 role 값을 확인해 general이면 마이페이지, admin이면 관리자페이지로 표시되도록 분기했다.
- 페이지별로 흩어진 header 관련 코드를 공통 로직 기준으로 맞추는 방향을 정리했다.
- article_id를 기준으로 ES 기사 데이터와 DB 조회 로그 데이터를 연결하는 흐름을 점검했다.

---

## 4. 느낀 점
- 저장된 데이터 값과 사용자에게 보여줄 표시값은 다를 수 있으므로 변환 계층이 필요했다.
- 사용자 반응 기능은 버튼만 추가한다고 되는 것이 아니라 기사 데이터, 사용자 데이터, 관점 데이터가 연결되어야 했다.
- 공통 UI를 사용하더라도 각 페이지의 JS가 다르면 실제 동작이 달라질 수 있었다.
- 권한별 화면 처리는 모든 페이지에서 동일한 기준으로 관리해야 했다.
- 프론트 화면 연결 작업은 API 데이터 구조와 함께 봐야 했다.
