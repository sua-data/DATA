## 1. 오늘 한 작업
- article_raw 인덱스와 news_economy 인덱스의 역할을 분리했다.
- article_raw에는 크롤링 직후의 원문성 데이터를 저장하는 구조로 정리했다.
- news_economy에는 전처리와 분석이 끝난 서비스 제공용 데이터를 저장하는 구조로 정리했다.
- raw_html, raw_text, source, press, url, title 등의 필드를 검토했다.
- 원본 데이터가 필요한 경우 다시 분석할 수 있도록 재처리 가능성을 고려했다.

---

## 2. 어려웠던 점
- 처음에는 기사 데이터를 하나의 인덱스에 넣어도 될 것 같았는데, 원문 데이터와 분석 결과 데이터의 목적이 달랐다.
- raw_html 같은 데이터는 저장은 필요하지만 검색 대상으로는 적합하지 않았다.
- 분석 결과가 잘못되었을 때 원본 기사 기준으로 다시 처리할 수 있어야 했다.
- article_raw와 news_economy를 나누면 구조는 깔끔해지지만, article_id 연결이 더 중요해졌다.

---

## 3. 해결한 방법
- article_raw는 원본 보관 및 재처리용으로 사용했다.
- news_economy는 화면 조회, 검색, 필터링, 집계에 사용하는 인덱스로 분리했다.
- article_id를 기준으로 두 인덱스를 연결했다.
- raw_html은 검색 부하를 줄이기 위해 인덱싱 대상에서 제외하는 방향을 검토했다.
- 원문과 분석 결과를 분리해 오류 발생 시 원본 기준 재분석이 가능하도록 했다.

---

## 4. 느낀 점
- 원본 데이터와 분석 데이터는 목적이 다르기 때문에 분리해서 저장하는 것이 좋았다.
- ES도 하나의 인덱스에 모두 넣는 것이 아니라 데이터 처리 단계에 따라 나누는 것이 효율적이었다.
- DB와 마찬가지로 ES도 처음 설계한 대로 바로 끝나는 게 아니라 계속 수정하면서 맞춰가는 과정이었다.
